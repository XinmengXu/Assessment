# Research Notes

## Feedback Provision Versus Feedback Use

The prototype separates feedback display from revision behavior. It records attempts, feedback type, feedback views, and revision events so researchers can study whether learners only receive feedback or actually use it in subsequent attempts.

## Outcome Analysis Data

- First-attempt and latest-attempt clarity scores.
- Word match score changes.
- Speech rate changes.
- Missing word and substitution reductions.
- Pre-test, post-test, and delayed-test scores can be joined later by participant ID.
- Expert pronunciation, fluency, intelligibility, and comprehensibility ratings can be joined later.

## Process Analysis Data

- Number of attempts per participant and task.
- Revision events after feedback.
- Score deltas between attempts.
- Transcript changes between attempts.
- Common missing or substituted words.
- Differences between control and explainable feedback conditions.

## Possible Experimental Design

- Control group: score-only automated feedback.
- Experimental group: explainable feedback with diagnosis, explanation, action guidance, and revision prompt.
- Participants complete assigned read-aloud tasks across one or more sessions.
- Researchers compare both outcome gains and feedback-use pathways.

## Suggested Measures

- Pre-test, post-test, delayed test.
- Expert ratings of pronunciation, fluency, intelligibility, and comprehensibility.
- System logs for attempts, revisions, scores, transcript changes, and feedback type.
- Learner questionnaire on perceived usefulness, clarity, trust, and motivation.
- Interviews or stimulated recall focused on how learners interpreted and used feedback.

## Ethics Notes

This app stores recordings locally. Participants should use assigned IDs instead of names. The automated feedback should be described as learning support, not as final assessment. Researchers should obtain ethics approval before formal data collection.
